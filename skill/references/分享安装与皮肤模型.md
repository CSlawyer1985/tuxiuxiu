# 分享安装与皮肤模型

2.5版随附四个模型，原始总计21,141,789字节（约21.1MB），比一轮增加约4.8MB；包括来源摘要、Apache-2.0／MIT许可、一键准备入口和锁定运行库。它们生成和细化候选，不等于完整覆盖或精细边缘已通过。安装成功不能代替真实照片验收。

| 模型 | 用途 | 原始大小 | 许可 |
|---|---|---:|---|
| Google Selfie Multiclass | 整图及局部皮肤语义候选 | 16,371,837字节 | Apache-2.0 |
| OpenCV YuNet 2026may | 多尺度定位多人脸，给出原片裁切位置 | 229,738字节 | MIT |
| Google Hair Segmenter | 单个人脸局部的发际线排除 | 781,618字节 | Apache-2.0 |
| Google Face Landmarker | 眼眉、嘴唇和鼻孔候选保护 | 3,758,596字节 | Apache-2.0 |

大小、SHA-256、固定下载地址和模型卡见包内`assets/skin-model.json`。原始权重未修改。Google模型卡和YuNet原始许可均有登记；不生成身份向量，不做人脸身份识别。头发模型面向单人，不能直接把整张多人会场当自拍处理。

## 首次准备

支持macOS／Linux，模型锁定环境需要已有Python3.12—3.14；Windows尚未适配。Mac解压后可打开“一键准备.command”，按提示同意准备；助手可执行：

本轮实机验证为Mac Apple芯片、Python3.14；Linux及其他Python版本尚未实机验收，需在接收者机器完成自检。

```bash
python3 <skill-root>/scripts/setup_runtime.py setup --yes
python3 <skill-root>/scripts/setup_runtime.py doctor
```

`--yes`仅在当前用户已授权首次准备时使用。否则先说明独立环境约400MB、普通包首次需要联网、照片留在本机；分享者的授权不代替另一位接收者授权。运行库安装在用户独立缓存，不修改系统Python。首次成功后复用，不重复安装或重复确认。缺Python时给出提示，不自动改系统或安装其他软件。

模型优先使用随包文件，缺失时才按授权从固定官方地址下载；大小与SHA-256必须相符。损坏文件停止使用，不覆盖旧文件。安装失败保留日志，重新准备另建环境，实际推理自检通过前不切换旧环境。自检应返回`ready=true`、`smoke_passed=true`；它验证皮肤六通道、头发两通道、五官及人脸检测四项实际调用、有限数值和运行库版本，不证明照片质量通过。`doctor`本身不下载、安装或改照片。

## 使用准备好的环境

```bash
python3 <skill-root>/scripts/setup_runtime.py run -- init --project <activity-root> --source <source-folder> --name <activity-name> --skin-detector semantic
python3 <skill-root>/scripts/setup_runtime.py run -- start --project <activity-root>
```

后续管线命令也经`run --`启动，避免装在独立环境却用系统Python执行。缺ICC的照片只有当前用户允许时才另加`--assume-srgb`。新活动默认语义候选；明确用`--skin-detector legacy`时只启用传统候选，不冒称语义分割。旧活动保存原检测模式与已修正蒙版，不随升级自动改选区。

语义模式常驻四模型。MediaPipe显式使用CPU；YuNet使用OpenCV默认后端及CPU目标，未单独验证每个底层算子。整图仅缩小做观察，人脸局部从整理方向后的原片像素裁出，再单独送入模型；不能从缩小的整图再次裁切，冒称保留原像素细节。

分别保存`skin`肤色候选、`texture`磨皮候选与`protection`像素保护。纹理范围必须是肤色范围的子集；调色不因某处不适合磨皮而被一并删除。眼眉、嘴唇、鼻孔及头发从皮肤候选中排除，不把五官排除直接当成全局色调的像素锁定。远处小脸或五官不可靠时，暂缓与该范围接触的整块连续皮肤磨皮，不能沿矩形框截断处理而形成新分界。此保守策略可能使相连皮肤更多区域进入复核，不能把暂缓解释为已完成精修。

诊断记录人脸候选数、五官定位成功数、暂缓范围、局部与整图冲突及时间；这些是机器筛查信号，不是准确率或自动质量批准。自动完成初选和细化，复核重点转向异常及效果检查，不能把逐图手工描皮肤作为正常批量流程。未通过技术核对时仍暂缓磨皮，不能伪造助手复核或用户确认。现有三张样图不足以证明所有场景可靠，未启用无条件自动放行。

缓存绑定原片、方向尺寸、区域、四模型摘要、候选算子及运行库版本；拉滑杆复用选区，不重复跑模型。已有人工修正优先；手工修改皮肤范围时，同步更新纹理范围并使旧核对失效。旧版两张蒙版的活动可继续，升级不静默覆盖人工修正或改变检测模式。

## 离线与分发

普通含模型包首次安装运行库需要联网，之后本地复用。平台离线包另含wheel，首次准备也可断网，但须匹配系统、芯片和Python主次版本；不包含Python安装程序。其他平台或版本需对应包或联网准备。

```bash
python3 <skill-root>/scripts/setup_runtime.py setup --yes --offline
```

默认缓存是当前用户目录内`.cache/event-photo-retouch`，可显式设置`EVENT_PHOTO_RUNTIME_ROOT`。缓存与虚拟环境不随Skill分发；接收者在自己的机器重新准备，不复制另一台电脑的虚拟环境。

构建用`build_skill.py --destination <new-directory>`，平台离线包加`--wheelhouse <wheel-directory>`。白名单只包含源文件、官方模型、许可及可选平台wheel，不含原片、活动水印、研究照片、账号、工作库或本机绝对路径。打包后在工作区之外解压、建立全新缓存、离线准备、实际推理与合成照片流程验证；包内模型和wheel摘要重新核对。
