# 自动批量管线与网页选样

分享版首次使用先按 [分享安装与皮肤模型](分享安装与皮肤模型.md) 准备独立环境与官方模型，并经 `setup_runtime.py run --` 执行下列命令。新活动可用语义皮肤候选，原有人工修正优先；候选仍需技术核对，不把安装成功当自动质量通过。

版本 2.6，2026-11-05。本文件是可移植业务核心的一部分。活动资料、真实照片及厂商资源均不随 Skill 分发。参数与文字要求的闭环另读 [微调规范](参数微调与修改要求.md)，缺成品水印时按 [三版水印流程](三版水印与网页选择.md) 制作并登记网页候选；交付后按 [归档与续跑](确认后归档与同场续跑.md) 收敛到已选完整链。

## 1．推荐执行方式

本地归档原件 → 分析每张照片 → 按实际条件选代表样片 → 生成候选、覆盖图和原像素细节 → 人在网页选择 → 本地自动批量处理 → 逐张核验和另存 → 下载与对话回传。

新活动／独立批次重新选样。同场追加先重新分析；原样片覆盖的标签、主体亮度代理范围及高亮比例内才可继承方向。数值接近只是初筛，明显出现新灯光、肤色问题或不相符场景时补样。仅当前照片的选择不能成为后续照片的统一方向。活动信息及水印已确认的，不重复询问。

“按推荐方案推进”授权实现与测试，不批准真实照片效果或新水印。真实活动不得由助手调用网页确认接口代替用户选样。合成测试的点击记录必须与真实活动隔离。

## 2．运行与依赖

包内提供自有传统像素执行器，使用随包脚本和已注明许可的模型。Python 3.10+、Pillow、NumPy 为当前必要依赖；OpenCV 是轻度保边柔化的可选依赖。当前服务启动／锁机制已面向 macOS／Linux 实现；不声称 Windows 已验证。macOS 有系统 Vision 和 swiftc 时，可本地定位脸、手、人物和文字候选；语义模式另使用随包四模型，不依赖macOS Vision，首次按安装说明准备。未准备模型时明确报缺失，不自动降级或把旧范围冒充语义分割。传统模式保留明暗校正和网页选区工具。

在活动已建立、原件已归档后运行；`<skill-root>` 与 `<activity-root>` 是实际路径占位，不能照抄为目录名：

```bash
python3 <skill-root>/scripts/retouch_pipeline.py init --project <activity-root> --source <source-folder> --name <activity-name>
python3 <skill-root>/scripts/retouch_pipeline.py start --project <activity-root>
python3 <skill-root>/scripts/retouch_pipeline.py status --project <activity-root>
```

`start` 返回本机网页地址，服务在本次宿主用户进程下运行，不注册开机服务。`serve` 可在前台运行；`prepare` 可只生成样片后退出，确认阶段不自行导出。已初始化活动直接继续，不重复 init。服务重开优先复用核对过的 run ID 和进程，端口改变时提供最新地址。

初始化的可选项：`--watermark` 指向活动内部已有资产；默认右下角、短边 15% 宽及 2.5% 边距只是待看样的起点。`--regions-file` 指向活动内部逐原片 SHA-256 绑定的既有定位／保护区 JSON；人脸观察框不能冒称皮肤选区。`--no-vision` 用于明确停用系统定位；`--assume-srgb` 仅在用户已明确允许该假设时使用。

JPEG／8 位 RGB PNG、TIFF、WEBP 在已验证色彩条件内处理；透明、高位深、未知颜色空间及损坏文件进入问题列表。有效 ICC 转 sRGB；Exif 声明 sRGB 时记录依据；无依据不静默贴标签。方向先整理为逻辑像素，导出方向为 1。原件保持原字节及拍摄信息；工作母版 PNG，交付 JPEG 质量参数 96、4:4:4，嵌入 sRGB。不是 RAW 开发或高动态范围修复。

## 3．当前候选实际做什么

| 方案 | 当前实际处理 |
|---|---|
| 自然校正 | 受限曝光增量、暗部／高光曲线、温和对比和锐化；不作局部肤色染色 |
| 明净通透 | 相对更强的受限层次调整；可靠皮肤候选中的轻微明暗及逐人蓝紫反光估计纠偏 |
| 柔和人像 | 较温和层次、受限皮肤明暗／偏色协调；有 OpenCV 且选区可靠时轻度保边柔化 |
| 保留原貌 | 不调色；仍按已展示和确认的色管／导出方式处理，可独立合成确认水印 |

以上是本地像素算子及起始候选，不是跨活动固定风格标准。基础候选完全不依赖 LUT。每图根据主体和全图分布分别确定受限参数，不以屏幕亮度代替面部曝光，不把亮度代理值变成所有人的肤色目标。

当前没有自动灰卡识别、准确全局白平衡估算、通用红黄肤色模型、全可见皮肤覆盖保证或全图智能降噪。诊断、配方及能力记录须如实列出这些缺口；复杂混合光和未覆盖皮肤部位进入复核或人工细化，不能因为有“人像”方案就填所有基础模块已完成。其余基础调色方法仍按《基础调色与肤色精修规范》在可用传统工具中实施并重新出样。

## 4．人在网页作出的决定

- 对比同一张原片与候选；分别检查整图、分享尺寸、面颈与手部原像素细节。未定位人物时展示画面中心细节，并明确不能据此证明无人或皮肤已覆盖。
- 查看橙色皮肤候选、蓝色保护区。必要时用矩形／画笔增减选区，保存后生成新版本并使该图旧确认失效。语义模式自动细化整图皮肤与原片人脸局部；肤色和纹理范围分开，异常连续皮肤暂缓磨皮。传统模式仍只生成保守面颈／手部候选。自动初选不能宣称所有皮肤均已准确覆盖；未覆盖处进入复核，不把每张都手工补选当正常流程。眼眉、唇、发际线、衣物、屏幕和近肤色背景必须排除或保护；蓝色反光脸不能使蓝衣服整片变成皮肤。
- 自动候选未完成全可见皮肤、特征排除、过渡及纹理技术核查前，原尺寸样片、快速预览和导出实际暂停磨皮，网页显示原因并保留强度草稿。额头、耳颈、肩胸等出现覆盖遗漏时先修选区，不能靠提高强度掩盖；完整门槛及绑定记录遵循《参数微调与修改要求》。人工蒙版须持久化并绑定原片，重启不能恢复成旧自动范围。
- 选择本批待处理照片或仅当前照片；可不同照片分别确认方案。皮肤精修需要本图核对记录，未核对条目进入复核，其他已确认照片继续。
- 水印按 [三版水印流程](三版水印与网页选择.md) 分区展示：中间上方始终保留原片与当前修图效果的大图对比，下方并排放同一张照片的三版水印叠加预览，点击可放大；三版水印不能替代核心修图主预览。右侧修片方案、参数及相关检查在上，独立水印素材选择在下，不放带照片的效果缩略图。内容、位置、比例和视觉版本一起确认；选择“保留原貌”也必须在中间看到有水印预览，不能导出未展示的叠加效果。
- 错图、无法解码或效果不适合的照片逐项显示原因；可以重试、暂停、恢复、说明原因后跳过，或为当前照片再出一版。文字修改要求保存为待办并回传，受影响照片暂停旧效果导出；应用参数后先重新出样再确认。交付备注与修改要求明确区分，不执行任意文字或冒称已经改好。

网页按钮的明确确认、参数快照及范围保存为不可覆盖 JSON；技术推进、方向偏好、改规则及回传测试都不替代此确认。缩略图及快速预览不是工作母版，微调未更新为原尺寸样片时不能确认。页面刷新不会丢失服务器上的版本与确认。

## 5．绑定、恢复与导出

任务库位于活动 `scratch/retouch/workflow.sqlite3`；各运行版本分别保存原件摘要、完整尺寸基准／母版、选区、配方、覆盖图、预览、细节及 QA。选择绑定当前 revision、样片摘要及实际执行程序／界面／关键依赖版本。代码更新需重启并对受影响未完成照片重新出样，不能拿旧样片批准新算子。

重复提交相同选择只生效一次；旧页面、原件漂移、蒙版改变、资源变化或重复编号对应不同内容均拒绝。相同文件摘要跳过重复导入；同名不同内容另存。新选区用 generation 隔离正在执行的旧任务，旧任务不能恢复旧蒙版或冒充当前成品。

只有保存、重新打开、尺寸／方向／ICC 及摘要核验后才登记完成；写盘失败不是成功。成品另存唯一版本，不覆盖此前交付。恢复核对原件与成品，异常项进入复核。受保护核心在色管基准与无水印无损母版间保持一致；JPEG 重编码及水印后的像素不作同样保证。数值自查、人工选样与独立复核分开记录。

运行时 `retouch-workflow-1` 与人工审计 `批次绑定模板.json` 是不同记录：前者驱动状态和文件绑定，后者用于完整 11 模块及交付语义审计。不得将工作流数据库直接交给 `batch_contract.py`，也不得声称两种记录已自动等价转换。需要完整审计时按模板补齐实际模块、检查和证据，不将未测项填 pass。

## 6．当前对话回传与唤醒

只在宿主实际支持且用户授权后绑定当前对话 ID：初始化可加 `--conversation <current-conversation-id>`。网页不能指定其他对话、任意命令或脚本。确认后本地处理服务自行继续照片处理，不依赖聊天是否仍在生成。

启用前先明确已绑定当前对话，然后运行：

```bash
python3 <skill-root>/scripts/retouch_pipeline.py enable-callback --project <activity-root>
python3 <skill-root>/scripts/retouch_pipeline.py callback-test --project <activity-root>
```

适配器使用当前宿主已存在的 `codex queue --resume`，没有该能力时保留网页结果和选择快照，从当前对话读取继续；不安装全局后台代理。事件是通知，不能越过新的用户授权。只记录 `queued`／`failed`／`delivery_unknown`，返回码 0 不等于对话已被唤醒；请求继续失败的诊断也须保留。

当前对话真实收到对应事件后，核对活动与事件 ID，再用 `ack --project <activity-root> --event-id <id>` 标记 observed。不能仅为了把状态变绿而调用 ack。发送后断线或收据不明不盲目重发；先核对对话，必要时由人明确重试。服务退出期间不承诺监听，系统睡眠／宿主退出／网络与宿主状态可能延迟回传。

## 7．回归与封装

```bash
python3 -m unittest discover -s <skill-root>/scripts/retouch/tests -v
python3 <skill-root>/scripts/test_contract.py --destination <new-synthetic-fixture-directory>
python3 <skill-root>/scripts/build_skill.py --destination <new-package-directory>
```

测试使用合成图，不批准真实活动样片。保留故障、竞态、重启与浏览器证据；运行日志不包含会话令牌。包内含自有规则、模板、Python／Swift源码、网页资产、测试及注明来源许可的四个官方模型。构建后在独立路径运行测试与合成流程，校验源文件、包副本和 ZIP 一致；构建不等于全局安装或宿主已加载。
