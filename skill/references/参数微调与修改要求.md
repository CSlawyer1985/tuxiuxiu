# 参数微调与修改要求

版本 2.2，2026-11-05。用于网页参数调整、文字反馈、修改回传及新样片确认。依次区分用户风格选择、技术选区核对和实际参数执行。

## 1．文字如何进入流程

“需要修改效果”是待办，不是交付备注，也不是对旧效果的批准。网页提交后，原文、原样片版本、目标照片、作用范围及当时的参数草稿一起保存到活动 `input/activity-materials/修改要求_*.json`，产生 `revision_request` 回传。受影响照片撤销当前执行批准、停止旧效果导出；不改写已交付文件，不影响未涉及且已批准的照片。显式暂停状态继续保留。

收到回传后先核对当前活动、事件和请求文件，不盲目重发或重复处理。理解原文，检查对应原片和问题区域；采用可验证的传统算子、局部选区或受限参数实现。文字不直接执行任意代码，不以一句“不够亮”声称已经完成调参。缺陷位置或目标确实不清楚时，用对话弹窗或实际照片区域提出一个具体问题；能继续的未受影响照片先处理。

将当前参数草稿作为起点，按用户原话改动。参数保存为活动内 JSON 后，可使用：

```bash
python3 <skill-root>/scripts/retouch_pipeline.py tune --project <activity-root> --profile clear --scope current --photo-id <photo-id> --parameters scratch/tuning/adjustments.json
```

`--scope batch` 表示本批尚待处理的照片；当本批均已交付时，表示为本批生成新版本。已有服务会自行生成新样片，无需并行再启动另一个 `prepare`。服务未运行时可单独使用 `prepare`。原作用范围不能因处理文字而从单张扩大到整批。

参数改动后，待办进入“正在生成样片／等待确认”，不能标成修改已完成。只有请求所涉全部照片的新版本均得到确认，才将该待办标为已批准；可以逐张累计，确认无关照片不能关闭本请求。累计按各目标的 generation 绑定，更改某图参数或选区会撤销该图的旧确认。修改仍不满意时可提交下一条要求。原文和历史请求文件保持不变。

“仅作交付备注”必须由用户明确选择，不自动推断“不够亮”“有瑕疵”只是备注。交付备注保存回传，不解释成已完成的像素处理。

## 2．可调参数及语义

参数名称、边界、步长与模式由 `scripts/retouch/tuning.py` 提供，网页和执行端共用。常用四项先展示，其余在“更多微调”展开。所有值必须是允许范围内的有限数，未知字段、布尔值和越界值拒绝。

| 界面项目 | 记录字段 | 实际语义 |
|---|---|---|
| 亮度 | `exposure_ev` | 每图自动曝光增量上再加 EV，在线性 RGB 乘增益 |
| 暗部／高光／对比 | `shadows`、`highlights`、`contrast` | 现有曲线系数的受限增量，界面百分比不是厂商参数 |
| 饱和度 | `saturation` | Lab 色度缩放增量，例如 0.1 表示 a*／b* 乘 1.1 |
| 冷暖／绿红 | `warmth`、`tint` | 全图 Lab D65 的 b*／a* 增量，不是准确色温或灰卡白平衡 |
| 肤色提亮／红润／冷暖 | `skin_ev`、`skin_da`、`skin_db` | 已核对皮肤作用区内的亮度与色度增量 |
| 磨皮／锐化 | `skin_smooth`、`sharpen` | 明确覆盖此算子的混合强度，属于绝对强度，不再次加在默认强度上 |

同一向量叠加在各图自己的自动配方上，不把整批曝光写成一个固定目标。两项强度覆盖及每图完整最终参数都要记录；逐人反光纠偏 `skin_balance` 也属于完整配方，不能从未选作样片的照片快照中漏掉。旧活动补样时需要从原件补齐分析，不能无声省略。

磨皮仅作用可靠皮肤区域，OpenCV 不可用时禁用该项；不因为有滑杆就声称实现了语义皮肤、自动去痘或所有瑕疵修复。超出当前非生成式能力的文字要求说明具体限制，继续可完成部分。

### 调节幅度与响应校准

滑杆须覆盖可辨认的调整幅度，低档保留细调空间，中高档应在同一照片、同一作用区上显示逐步增强的变化；不能只改显示百分比或扩大刻度而不验证实际像素响应。不同参数分别校准，不统一乘一个倍数。当前控制范围如下，真实定义仍以 `tuning.py` 与执行器为准：

| 控制 | 人工调整范围 |
|---|---|
| 亮度 | −1.5 至 +1.5 EV 增量 |
| 暗部 | −0.5 至 +1.0 曲线系数增量 |
| 高光 | −1.5 至 +1.5 曲线系数增量 |
| 对比 | −1.2 至 +1.2 曲线系数增量 |
| 饱和度 | 色度缩放增量 −0.8 至 +0.8 |
| 冷暖／绿红 | Lab b*／a* 各 −12 至 +12 |
| 肤色提亮 | −0.6 至 +0.6 EV 增量 |
| 肤色红润／冷暖 | Lab a*／b* 各 −10 至 +10 |
| 磨皮 | 0 至 100% 绝对强度 |
| 锐化 | 0 至 150% 绝对强度 |

扩大人工范围不自动提高方案的默认数值，也不把高档效果当作新批默认。曝光、肤色等端点叠加本图基础参数后必须仍在执行器允许范围内，不得出现滑杆能拉到而服务端拒绝的失效区间。强调整后的截断、偏色及纹理仍由既有样片和保护区检查处理，不自动批准成品。

磨皮采用非生成式保边滤波：在既有皮肤候选的连通区域内，随实际像素尺度和强度调整滤波半径、颜色差阈值及回混比例；不向衣物或背景扩张选区。眼眉、嘴唇等排除区及保护区保持不变。每个区域的直径、空间／颜色阈值、回混及实际覆盖记录到 QA；0 为不执行。使用冻结的同一输入处理各区域，并给滤波边界足够邻域，不在分块接缝重复磨皮。能力不足或选区缺失时说明限制，不能靠提高强度冒称已修到未覆盖皮肤。

响应校准先保留原片和旧版上限效果，再用代表人像比较 0、25%、50%、75%、100% 等档位，检查真实纹理变化、五官边缘及面颈过渡。新算子版本重新出样，旧确认不批准新像素；调参仍保留用户的真实草稿数值，不在升级时擅自映射到更高强度。

### 磨皮覆盖门槛：不得出现半脸或额头分界

自动人脸框、椭圆和肤色置信度只用于初选，不能直接作为最终磨皮范围。逐图核对发际线以内的整个额头、太阳穴、面颊、下颌、可见耳部、颈、肩胸、手臂手腿。阴影、雀斑、毛孔和不同受光不能成为皮肤内部的选区缺口；平滑作用区内部保持连续，羽化放在实际皮肤外缘和特征排除区周围。不能通过放宽颜色阈值把衣物、头发和背景一起磨平。

执行前四项必须全部通过：①全部实际可见皮肤覆盖；②眼眉、唇、鼻孔、发际线及应保留细节排除；③额头上下、脸颈、颈肩及边界过渡无硬分界；④原像素下纹理和五官正常。按全图、原像素细节和多个强度核查；用提高强度暴露遗漏，不能把高档当交付默认。某部位不适合处理时记录原因与明确例外，不能悄悄只磨半张脸。

程序在原尺寸候选、快速预览和导出共用磨皮门槛：当前蒙版没有绑定的完整技术核对记录时，实际 `skin_smooth=0`，QA 写明暂缓原因与请求强度；网页停用该项并保留强度草稿。普通“已看选区”勾选不能替代四项技术核查。先完成可安全执行的其他模块，补齐选区后从原片重新出样，重新由用户选择效果。

人工选区以 `mask_overrides` 绑定原片 SHA-256、逻辑方向、原尺寸及两张蒙版摘要。重启和程序升级不得退回旧的自动椭圆；来源、方向、尺寸或摘要不符时拒绝复用，不能自动缩放。网页保存蒙版沿用该持久化机制，任何蒙版更改均使旧技术核对失效。

## 3．快速预览与正式确认

快速预览调用真实算子处理较小图像，仅供调参反馈；不登记成品，不产生批准。它与原像素柔化／锐化的观感可能不同，确认依据始终是后来生成的原尺寸样片与细节。

快速预览、原片对照及更新后的调色效果统一显示在中间上方的核心修图主预览，该主预览始终保留。三版水印对照位于其下方并排展示、点击可放大，不能替代主预览。右侧先放修片方案与参数，再放独立水印素材选择，不额外放一张带照片的微调小预览。有三版水印时，各版对照须使用当前同一张照片及同一组修片参数，未同步生成的版本显示待更新，不能混用旧参数效果。水印选择与对照的完整布局遵循 [三版水印与网页选择](三版水印与网页选择.md)。

拖动参数后，确认按钮停用；“应用微调并更新样片”将参数、范围和当前版本保存，产生新 revision、配方和完整尺寸母版，原确认不再用于新参数。新样片完成并核对后才能确认。当前控制值尚未保存、文字要求仍待处理或版本过期时，不能确认旧效果。

客户端快速请求按当前照片、方案、参数及版本核对，过期响应丢弃；切图不丢其他照片草稿。浏览器刷新恢复草稿，但不将草稿冒充已生成样片。原片始终作为计算起点，不在上次处理结果上反复叠加。

## 4．参数回传、技术核对和历史

网页确认文件包含 `parameter_snapshot`：目标照片 ID、方案、用户微调向量、完整实际参数、是否已验证完整候选及配方引用。大批次只保存一次全量快照；逐图状态和回传携带 `parameter_snapshot_ref` 的路径与 SHA-256，不把整批参数重复拷进每张照片或塞进命令行消息。按该引用核对后读取全量内容，不因消息只列引用就说参数没有回传。

风格和水印必须由真实用户确认。技术性的选区检查可以来自用户勾选，也可以来自助手实际查看覆盖图、原像素边缘／面颈手部并写出的独立技术记录；后者只是助手自查，不称独立复核，也不得在 `skin_reviewed` 中伪造用户勾选。

助手技术记录为活动内 JSON：`schema_version=assistant-technical-mask-review-1`、`actor=assistant`；`binding.input` 与 `binding.masks` 必须是当前原件和全部蒙版的完整 artifact；`checks.technical_result` **必须是布尔 true**，失败、未知或任意文字均不通过。附实际核对证据与覆盖限制。登记为照片的 `assistant_technical_review` artifact 后，运行时重新核对摘要和绑定；换原件或蒙版会使该记录失效。这不是授权助手选择风格，也不能借此跳过用户对新效果的确认。

允许磨皮还须将 `visible_skin_complete`、`exclusions_checked`、`transitions_checked`、`texture_checked` 四项分别记录为布尔 true，并附当前照片的实际检查证据；旧记录只写“技术通过”不足以解锁。助手检查是自查，不称独立审核，不替用户确认样片。

已交付成品被保留，微调仅生成新版本；页面可下载此前成品，活动记录区分历史选择和最新选择。新活动仍重新选代表样片，同批只有已确认并被实际场景覆盖的方向及参数向量才可继承。资料、预览、风格意见和私有活动水印不进入 Skill 分发包。
