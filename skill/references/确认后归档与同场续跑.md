# 确认后归档与同场续跑

用户确认修片方向后，不再无限累积未选方案和旧试修图。当前默认在本批所选照片导出、重新打开及摘要核验完成后自动收敛；处理中、待确认、异常待处理或修改要求未落实时不清理。这样既能控制项目体积，也保留中断时需要的素材。

## 保留什么

- `input/` 中原片、用户素材和原始确认记录，以及 `output/` 中所有已交付成品，始终保留。
- 每张已完成照片保留已选方案的完整链：无损基准、所选母版、当前蒙版、诊断与配方、QA、原片及结果预览、原像素细节、导出复核和用户确认。
- 保留当前活动的已确认水印、版式参数、适用条件、逐图测量规则、统一微调增量及确认范围。配置中的既有区域清单所引用的资源也必须保留。
- 当前网页只展示保留的已选方案；需要重新比较时先“为这张另试一版”，从原片重建候选，不能显示已经移走的文件或把旧确认套到新候选。
- 已有完整且内容核对一致的成品 ZIP 时，网页下载直接复用；避免再存一份相同照片的缓存包。历史成品不因清理而覆盖或移走。

未选候选、失效试修、过期预览／细节以及可重建的活动运行缓存可以移入废纸篓。三版水印选定并最终交付后，未选水印也不再占据活动的工作素材区；保留名称、选择记录与清理清单，不在同场追加时重新设计。

## 清理执行与记录

`init` 默认设置 `retention_policy=selected_only`。运行服务在本批完成后串行执行归档；原有未设置策略的活动不被静默清理，需要本次用户授权后迁移。当前自动废纸篓落点已按 macOS 实现和验证；无法找到同卷、可核验废纸篓时报告归档失败，保留成品，不降级为永久删除。

```bash
python3 <skill-root>/scripts/retouch_pipeline.py compact --project <activity-root>
python3 <skill-root>/scripts/retouch_pipeline.py compact --project <activity-root> --apply
```

无 `--apply` 只盘点；命令行执行前停止该活动服务，避免与运行任务并发。自动流程由服务内部串行执行，不需要停止服务。每次清理先核验保留链，记录精确路径、文件数、字节数、校验值、保留项、授权来源和清理前状态快照，再同卷移动到当前用户废纸篓，逐项核验源路径消失及废纸篓内容摘要。

状态先指向完整保留链，再移动非必要文件；中途失败会留下 `retention_pending` 与清单，可以继续，不能为了状态变绿而删除记录。失败后不连续自动重试，核对后通过命令行继续。清单和结果保存在活动 `scratch/retouch/retention/`；历史 JSON 中已退役的路径只是审计信息，不再作为实时网页资源，移动位置以清单为准。

移入废纸篓不等于真正释放磁盘空间。不得自动清空废纸篓或永久删除。恢复前停止服务，对照原路径、废纸篓内容和状态快照，核对冲突后再恢复，不覆盖原路径后来生成的文件。

## 追加同场照片

确认记录与调色／分析实现的签名单独保存，网页和归档代码的调整不取消已确认方向。实际调色或分析算法、依赖库发生变化时不能继承为同一执行实现，必须重新看样。

新照片重新做色管、测量、分类和选区；条件在本批已确认样片覆盖范围内时，复用风格与允许的微调增量，逐图自适应处理。新光线、曝光、偏色或人物条件超出范围，只为受影响子组补样。仅当前照片的授权不扩展为未来整批默认，人像新图仍须本图可靠选区检查，不能继承旧照片坐标或伪造核对。

旧版活动如因界面升级丢失了续跑选择，可在用户明确授权继续相同已确认方案后使用 `compact --apply --adopt-existing-confirmation` 迁移。它逐图核对原始网页确认、所选母版、原件与成品摘要，并验证当前有效配方与已选配方相同；不匹配就停止，不能把“喜欢某个方向”制造成确认。
