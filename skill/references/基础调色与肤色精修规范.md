# 基础调色与肤色精修执行规范

版本：1.1。制定日期：2026-11-04；可迁移结构更新：2026-11-05。状态：用户已授权落盘的工作区执行细化。

本文件供基础调色、混合光纠偏、人像肤色、轻度磨皮及商业会议照片处理任务按需显式读取。与包内《修图业务规则》第 4.1—4.4、7 节共同适用；原件保护、非生成式处理、每批选样、同场水印及用户确认范围仍按入口执行。

这是本工作区的方法和记录规范，不是任何一批照片的固定配方。算子、数值和效果必须由本地工具与本批样片验证。单 LUT 对比只算风格试验，不能登记为整套基础调色与肤色精修已经通过。

配套文件：`references/基础调色与肤色精修_记录模板.json`。路径以 Skill 根为基准，记录内的材料路径以活动根为基准；每批复制模板到活动的 `scratch/`，填入实际内容，不把空模板当作已执行记录。

## 1．一次处理的完整路径

默认执行顺序如下；不需要的模块仍须评估并记录跳过理由：

1. 锁定原件、方向、尺寸、元数据和色彩解释，建立色彩管理后的基准。
2. 测量全图与主体，按本批原片分组，选代表性照片。
3. 建立保护区、人物与皮肤候选区，核对后确定实际可处理范围。
4. 按噪声情况作必要的温和预降噪，校正可信的全局白平衡与基础影调。
5. 在可靠区域处理局部曝光和混合光偏色，调整必要的分色相色彩。
6. 分别协调每个人的肤色、皮肤明暗、面部／非面部质感，检查过渡。
7. 按本批选择评估可选 LUT；再次检查皮肤、中性物、品牌色及保护区。
8. 在实际交付尺寸下进行适度输出锐化，最后合成已确认水印并导出。
9. 用相同尺度比较原图、基础校正版及完整候选，完成指标与视觉验收，再按本批确认范围批量执行。

可以因模块依赖调整顺序，例如先降色噪再提亮深暗部；必须记录实际顺序和原因。改变顺序后重查颜色、截断、选区及纹理，不能假定这些算子可任意交换。

## 2．输入、色彩和数值基准

### 2.1 原件与色管

- 复制并校验原件，不改写 `input/`。处理方向按 Exif 与实际内容核对，不自行裁切、旋转构图或改变长宽比。
- 有有效 ICC 时按该配置解释并转换，记录输入／工作／输出配置、渲染意图与工具。不得给未知像素简单贴一个新 ICC 后冒称已经完成颜色转换。[Pillow 色彩转换文档](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html)
- 无 ICC 时检查 Exif 等声明；例如 Exif ColorSpace 为 1 可作为 sRGB 声明依据。若仍无可靠依据，明确写为颜色空间假设，先用样片核对，不能把假设登记为实测结论。没有理由时不额外要求用户提供其也无法确定的色温或相机参数。
- 共享照片默认可采用明确的 sRGB 工作及输出约定；有品牌、打印或其他颜色要求时依具体要求设置。LUT 资源是数值表，不按普通照片对其随意做 ICC 转换。
- 中间计算优先使用浮点或足够位深，减少多次 8 位往返。只能处理 8 位的模块须记录量化环节；浮点计算不等于原片具有 RAW 动态范围或新增真实细节。

### 2.2 单位不能混用

| 控制 | 必须声明的单位与不变状态 | 使用约束 |
|---|---|---|
| 曝光增量 | 本地处理 EV；0 为不变 | 在线性 RGB 中采用 `2^EV` 才对应明确的倍率；不是从 JPEG 推断出的拍摄曝光误差 |
| 白平衡／通道增益 | 工作空间内的无量纲倍率；1 为不变 | 写清处理域与归一化方法；RGB 增益、色温、色调不是同一个参数 |
| 曲线及分段影调 | 输入输出域、控制点、插值和作用区；恒等曲线为不变 | 高光／阴影滑杆名称不能代替本地算法定义 |
| HSL／HLS | 色相角度与循环范围、饱和度／明度尺度；色相增量 0、倍率 1 为不变 | HSL 明度不是 CIELab 的 L*；近灰区域的色相不可靠 |
| Lab 皮肤纠偏 | L*、a*、b* 的实际标度和参考白；增量 0 为不变 | 不混用不同白点、8 位偏移值与浮点值，不设通用肤色目标 |
| 平滑与纹理 | 原始像素半径、滤波输入尺度、值域参数、回混比例 | 空间半径与颜色差阈值单位不同，不能直接照搬另一工具的数值 |
| LUT／图层回混 | 本地归一化比例、采样布局、作用域、混合颜色空间；0 为不变 | 厂商 70、80、alpha 等不直接解释为 70%、80% |
| 输出锐化 | 实际输出像素半径、强度、阈值及掩膜 | 不用预览图半径直接处理原始大图 |

OpenCV 的 8 位与浮点 Lab 表示不同；其常规图像通道顺序也可能是 BGR。调用前核对 RGB／BGR、归一化、转换标志与白点，先在小色块上检查黑、白和非中性色的往返。OpenCV 浮点 Lab 与其他 ICC Lab 不能仅凭名称相同直接混算。[OpenCV 色彩转换文档](https://docs.opencv.org/4.x/de/d25/imgproc_color_conversions.html)

## 3．本批诊断与代表性样片

### 3.1 必须分区域测量

在统一的工作颜色解释下，至少记录全图、主体、可靠面部／皮肤观察区的 P5／P50／P95、暗部与高亮比例、RGB 各通道及全通道截断、区域明暗差。记录计算域、阈值、区域来源和统计分辨率。

编码 RGB 加权值只作为亮度代理，不能标作物理亮度或精确曝光档数。若使用线性亮度，单独注明转换与公式。清晰度、噪声代理必须在相同区域、尺度和预处理下比较，不能将代理值当作绝对质量分数。

可靠面部观察框可用于诊断，但不是精确皮肤选区；自动检测未检出也不代表无人。工具没有可用检测器时人工核对，不编造检测数量或皮肤覆盖率。

### 3.2 分组与选样

按实际存在的问题多标签分组，例如曝光合适、暗脸亮屏、混合光、明显偏色、强反光、多人受光不同。不要强迫每批凑齐相同分类。

从各类实际原片选少量代表：既覆盖典型情况，也覆盖可能失败的暗部、强偏色、多人及重要文字场景；同一张可以代表多个条件。每批重新选方案与强度，既往偏好只作参考。照片数量少时按实际数量选，不人为增加样片。

共同的基础校正确定后，比较适用的风格层或不使用 LUT。不要给一个候选额外调亮、另一个保持原样，却把差异都解释为 LUT 的优劣。

### 3.3 参数如何从本批样片确定

1. 先为每个诊断问题指定要改善的区域、依据和验收项目；没有可靠改善依据的模块保持不变或跳过。
2. 从算子的不变状态开始，以已校准单位小步改变一组相关参数，比较原状态和少量有意义的候选。影调、肤色与纹理分别校准，避免同时改变多个模块后无法定位改善或损伤来源。
3. 选择能解决该问题、同时通过保护区、颜色、截断和纹理检查的较轻强度，记录这类原片允许变化的参数范围、停止条件与适用条件。没有通过的候选就回到诊断或换方法，不强选一个预设。
4. 同类后续照片依据自身指标在已确认范围内调整；原片差异超出样片覆盖、需要突破范围或出现验收失败时，对受影响子组补样，不无限自动加码。样片指标可作参照，不强迫不同人物达到相同肤色数值。
5. 模块内部校准与常规降强度由助手完成，向用户提交少量完整代表样片供选择；不逐个滑杆反复询问。同批已确认范围内继续处理，沿用 《修图业务规则》 的追加和补样规则。

## 4．选区与保护区先核对

- 分开保存主体区、实际皮肤区、特征排除区、背景／光源区、中性参考区与事实内容保护区，不用一个人脸矩形完成全部任务。
- 皮肤选区采用人物范围、颜色候选和人工检查共同确定；颜色相近的木材、皮衣、屏幕、背景不能因此入选。不同人物建立各自范围；脸、耳、颈、胸前、手臂、手、腿按实际露肤核对。
- 眼睛、眉毛、睫毛、眼镜、唇、鼻孔、发际线、饰物以及有身份意义的痣、疤痕等不得被常规磨皮默认抹除。牙齿、眼白不跟随皮肤染色。
- 屏幕、横幅、桌牌、胸牌、文件、Logo 等先标保护区；人物遮挡屏幕时从屏幕保护区排除人物，避免把发言人一起锁住。
- 明确设为像素锁定的核心区，以色彩管理后的基准为参照，不参与曝光、白平衡、HSL、LUT、平滑和锐化；过渡带另行羽化并检查。普通内容保护区也须检查可读性、品牌色和几何完整性，不冒称其逐像素相同。
- 选区以原始逻辑方向和尺寸登记；缩略图坐标映射、羽化半径、缩放因子须可复现。先看整图覆盖，再看边界和低置信区域；不能沿用旧照片坐标。
- 磨皮前先逐图完成全部可见皮肤覆盖、五官排除、连续过渡、原像素纹理四项检查；额头上部、耳颈和肩胸不能被人脸椭圆或颜色阈值遗漏。阴影、雀斑或毛孔不得形成皮肤内部的置信度断层。羽化沿真实外缘及特征边缘进行，不在额头或脸颈中间出现作用分界。
- 选区低置信或四项未通过时，该图暂停磨皮，保留可完成的调色，补选并复查后从原片重出样。不能只提高强度补救遗漏，也不能以不可靠全自动选区换取“全部皮肤已精修”的表述。技术记录及程序门槛见《参数微调与修改要求》。

## 5．基础白平衡与影调组合

### 5.1 白平衡先处理可信的共同偏色

1. 选同一照明条件下、未截断且非强反光的可信中性物；记录区域和它被视为中性的依据。投影画面、发光屏幕、深黑衣服、反光高光默认不能直接当作白平衡目标。
2. 先判断偏色是否全局一致。若是，使用温和通道增益或已验证的色温／色调工具，逐步改善中性物和人物；没有灰卡时不声称恢复准确开尔文色温。
3. 若不同区域受蓝色屏幕、暖灯或其他光源分别影响，不用一个全图白平衡强行解决；转入第 6 节局部混合光处理。
4. 调整后重查人物、白纸、灰墙、黑衣的层次和亮部截断；不能为了让背景变中性而把人物变黄、变红或变灰。

### 5.2 明暗控制的职责

先建立主体和中间调的基本明暗，再分别控制亮部、暗部和端点，最后微调对比并回查曝光。影调控制会互相影响，不能把多个滑杆都大幅推高。以下是职责划分，不是外部软件处理函数的数值映射。[Adobe 影调调整流程](https://helpx.adobe.com/lightroom-classic/desktop/help/tone-control-adjustment.html)

| 控制 | 何时调整及如何判断 | 必须避免 |
|---|---|---|
| 曝光／中间调 | 主体整体偏暗或偏亮时先调整；亮屏占比大时优先主体统计和目视 | 以全图平均值驱动整图提亮，导致屏幕和皮肤高光溢出 |
| 高光 | 控制仍有层次的亮部，让亮面过渡平顺 | 把已经全通道剪平的 JPEG 高光变暗后称为恢复细节 |
| 白色／白点 | 调整靠近白端的收束和亮部余量；兼顾白衣、白纸 | 与皮肤美白混淆，或为了白净把所有亮部压成同一灰阶 |
| 阴影 | 提升有信息的暗部，观察面部、衣服和环境层次 | 黑衣变灰、深暗噪点放大、背景普遍漂浮 |
| 黑色／黑点 | 保留合理黑位和暗部锚点，与阴影调整共同检查 | 为去灰压死脸部暗面，或为提亮抬掉全部黑位 |
| 对比／曲线 | 在前述控制基本平衡后微调中间层次；曲线应平滑并保持合理单调 | 强 S 曲线、局部断阶、轮廓光晕、过度 HDR |
| 清晰度／去雾 | 仅在确有灰雾、逆光泛白或层次不足时有限使用，可限制背景 | 把通透感等同全局去雾、加锐或提高局部对比，放大皮肤粗糙 |

局部暗脸与亮屏同时存在时，将主体提亮与屏幕保护分开；不要靠拉高全图曝光再压低整张图来互相抵消。若抬亮显露噪声，降低提亮或作经过验证的有限降噪，不补造纹理。

RGB 某通道截断与全通道截断分别记录；源图缺失的信息不能由传统调色凭空恢复。对比、饱和度或白平衡变化后重新查看截断位置。[Adobe 影调与截断说明](https://helpx.adobe.com/lightroom-classic/desktop/process-and-develop-photos/image-tone-color.html)

## 6．混合光与分色相调整

### 6.1 局部纠偏

- 先定位实际受影响的人或部位，结合肤色、衣物与可信中性物判断光源作用，不能只看某个 RGB 通道较大就推定偏色。
- 蓝／紫反光只在受影响区域逐步补偿，检查改善蓝偏时是否又引入黄／橙；绿／洋红、红／黄偏色同样分开判断。沿光照方向平滑过渡，保留合理的环境冷暖关系。
- 同一人物面部、颈部和手部采用一致的颜色逻辑，但受光不同可以使用不同增量；不以同一个数字抹平立体光影。不同人物不向固定肤色数值靠拢。
- 无可靠参考、通道已严重截断或选区不稳时采用较轻修正或保留局部原貌，写明限制，不强行让全部皮肤“达到标准”。

### 6.2 HSL／HLS 与颜色范围

- 只有全局与局部白平衡仍不能解决的问题，才按需要进一步分色相处理；分别记录色相、饱和度和明度，不将三者视为同一个“美白”滑杆。
- 用空间选区与颜色权重相交，限制实际作用范围。红、橙、黄可能同时包含皮肤、木背景和品牌色，不能全图统一降红黄饱和度来处理脸部。
- 肤色优先小幅、连续地协调色相与浓淡，保留唇色和自然红润；近灰、极暗和截断区域不依赖色相角作可靠判断。色相跨越 0／360 度时应正确环绕，权重边界平滑。
- 调高某色明度后再查该区饱和度与纹理；变灰、变白或色块出现时同时回查颜色、明暗和选区，不能只回退曝光。
- 背景风格调整与皮肤校正分开，并保护文字／标志。使用任何“自然饱和度”工具前验证其实际作用，不假定本地实现会像某商业软件一样自动保护肤色。

## 7．肤色精修：颜色、明暗、质感分开

### 7.1 颜色与明净感

先去除明显异常偏色，再协调颜色浓淡和皮肤明暗；不将肤色脱饱和或提亮本身称为通透。没有异常红斑的人不默认去红；没有黄偏的人不默认去黄。白皙方向也须保留原有肤色差异、血色和自然唇色。

可在统一参考白、已知转换的 Lab 等空间分离明度与色度，但目标来自本人的可信受光区域、本批样片和用户反馈，不来自固定 RGB、L*、a*、b* 数值。每个人逐项记录面部、耳颈与非面部实际覆盖，检查下颌、领口、袖口、手腕的过渡。

### 7.2 局部明暗

对局部暗面采用宽而平顺的明暗调整，避免沿人脸轮廓画出发亮边缘。面部亮而颈手暗时先诊断是否受光差异或漏选，不把所有部位强行拉到同一亮度。正常鼻梁、额头等高光和真实光影保留；油光或强反光的缓和不能变成平涂脸部。

### 7.3 轻度磨皮、降噪与纹理

1. 先在原始像素的 100% 下判断是否有需要处理的粗糙或噪声。人脸太小、原片已柔焦、压缩较重或缺少真实细节时，跳过进一步磨皮并记录原因。
2. 仅在核对过的皮肤范围内使用经过测试的非生成式保边方法。空间半径按原始人脸尺度设定；颜色差阈值按滤波输入域设定，不能套另一个分辨率或工具的数值。
3. 颜色噪点与亮度粗糙分别处理，面部与非面部可用不同强度。双边滤波等方法可作为候选，但保边不等于必然保住毛孔，仍需实际观察。[OpenCV 保边滤波说明](https://docs.opencv.org/4.x/d4/d13/tutorial_py_filtering.html)
4. 若采用多尺度／频率分解，记录实际分解、纹理层权重及重建方法；不能仅因厂商存在高／低层参数名，就冒称已经恢复其算法。
5. 滤波结果与原图按独立强度及有效蒙版回混。需要颜色修正不意味着必须磨皮，需要磨皮也不意味着必须提亮或去红。
6. 五官、眼镜、发际线、饰物和应保留的身份细节排除于磨皮；微小瑕疵只能做允许范围内的传统柔化，不生成新皮肤。出现蜡感、色块、边缘损伤或纹理损失时先回退相关模块，不靠后续锐化伪造回来。

## 8．通用局部合成与风格层

本地可采用明确的有效权重：`作用区 × 置信度 × 颜色权重 × (1 − 保护区)`。使用哪些因子应由任务决定，不要求每张图都依赖颜色阈值。明确归一化到 0—1，并声明处理和回混的颜色空间。

- 作用权重为 0 或保护核心值为 1 时，保持相应工作基准像素；两个不同人物的区域重叠时记录归属或经过验证的混合方法，不把权重无界相加。
- 参数为不变状态时，模块应通过不变性检查。颜色转换自身可能有量化误差，单独测量，不能把每次往返造成的改变都解释为美化。
- 可选 LUT 位于基础校正与皮肤处理之后，作为单独可停用的风格层；启用后必须重查肤色、白纸、衣物与品牌颜色。若它破坏已校正的皮肤，限制作用区、降低强度或不用，不强行保留。
- LUT 的布局、数值域、采样、资源摘要及混合语义须验证；本地 sRGB 采样约定只适用于已验证的资源与处理链。每批重新选择是否使用及强度，“通透 25%”只属于曾展示的那组测试。
- 必须提供“基础校正＋肤色精修、不加 LUT”的可比较候选，避免用风格层掩盖基础校正未完成。

## 9．输出锐化、水印与导出

先以实际交付尺寸评估锐化；保留原分辨率时按该分辨率设置，有另行授权的缩小版时对缩小版单独评估。纹理较差、眼镜边缘、高反差文字和皮肤需检查光晕；平滑过的皮肤不被全图锐化重新放大噪点。眼睛、文字等锐化也不能生成原片不存在的细节。

最终调色与锐化后再合成已确认水印，保留其原色与透明度；不能让 LUT 或 HSL 再次改变 Logo。样张、水印确认与同场复用按 《修图业务规则》 既有范围执行，不为每次追加重做资产。

保存无损工作母版与必要的阶段版本，导出时记录尺寸、格式、位深、质量、色度抽样、ICC 和可保留的拍摄信息。最终 JPEG 的正常编码差异不作为像素锁定失败；锁定检查在对齐的无损工作母版完成。

## 10．验收：数值、区域、视觉共同通过

| 检查项 | 核对方法 | 不通过或未测时的处理 |
|---|---|---|
| 来源与几何 | 原件摘要、数量、对应关系、方向、比例和分辨率 | 修正归档或输出，不冒称原件未变或几何保持 |
| 颜色与单位 | ICC／Exif／假设、通道顺序、数值域、Lab 白点、模块单位 | 纠正解释与转换；不能凭视觉顺眼掩盖单位错误 |
| 明暗与截断 | 相同区域与尺度比较亮度分布、RGB 截断位置与数量 | 新增大片皮肤／文字溢出、死黑、断阶时回退；反光例外须单独标注 |
| 保护区 | 像素锁定核心在无损基准中检查；其余核对可读性及事实内容 | 修正蒙版、混合或后续算子，不能以 JPEG 相同作未经证实保证 |
| 肤色与覆盖 | 每个人的脸耳颈、实际手臂手腿；看发灰、过白、红黄／蓝紫异常与边界 | 回到选区、颜色或明暗模块；不声称没有可靠处理的部位已完成 |
| 纹理与锐化 | 同一面颈手部在 100% 与统一分享尺寸下比较 | 有塑料感、色块、光晕、粗糙加剧则降低强度或停用对应模块 |
| 方案比较 | 原图、无 LUT 的基础校正完整候选、可选风格候选 | 缺基础候选时不能把 LUT 试验升级成整套精修通过 |
| 过程可复现 | 版本、算子、参数单位／值／范围、实际蒙版及输出摘要 | 补记录；没做的检查写未测，不填通过 |

必须保存输出前裁切／量化的越界及截断信息，不通过末尾强制截断把处理问题藏起来。数值容差根据位深、转换与采样验证声明，只解释对应计算误差，不能替代肤色或纹理验收。不设所有人物共同达到的亮度／色度目标，也不设脱离原片的统一画质合格分。

每个模块记录 `已评估并执行`、`已评估无需执行`、`能力或选区不足未执行`，并给出理由。后两者不冒称该部位已精修；未执行不阻塞能够安全完成的其他模块。样片仅在本批及其已覆盖条件内确认，明显新条件按入口补样。

## 11．工具、记录与当前能力边界

必须实际核对所选工具的版本、函数、输入格式与小数组结果，不以包名或版本号推定人像检测／分割／滤波都可用。不自动安装依赖或改变账号与软件状态。

执行时检查当前解释器、实际函数与能力；不要求固定电脑、固定工具版本或特定厂商应用。只读盘点和记录校验脚本需要 Python 3.10 及以上；涉及图像解码、方向和蒙版检查时需要可导入的 Pillow。照片处理另按实际工具选择 NumPy、OpenCV 或其他本地非生成式工具。缺少人像检测器时人工确定区域，不能把观察框当精确皮肤蒙版。本包不自动安装依赖；历史小数组测试不作为当前真实照片效果证据。

过程记录使用配套 JSON 模板，至少包含：批次与选样理由、输入摘要、颜色基准、每张／每个人的问题标签、参考与保护区、模块决定、实际参数和单位、前后同域指标、蒙版核对证据、无损母版与预览、水印版本、视觉与数值检查、用户原话及确认范围。

只有单 LUT 比较的批次不能由本规范落盘反向标为基础调色与肤色全流程已完成；历史偏好、样片与水印各自保持记录状态，不自动扩大。

### 四模型候选与批量异常筛查（2.5）

语义模式自动组合皮肤分割、人脸定位、单人局部头发分割和五官关键点。局部从原像素裁切，不从缩小整图二次裁切；不得用椭圆、矩形或肤色阈值直接替代皮肤语义范围。初选、细化、缓存和异常标记自动完成，避免逐张手工描选成为正常流程。

肤色与纹理范围分别保存，磨皮只作用于两者交集。小脸、遮挡或五官定位不可靠时，暂缓相关整块连续皮肤磨皮，保留可完成的调色；不能沿矩形框或不同检测区域产生半张脸磨皮的分界。头发、眼眉、唇及鼻孔排除需在原像素检查，关键点与语义冲突进入复核。自动候选和数值筛查不等于技术复核或用户选样；没有独立标注集验证时，不以少量样图宣称准确率，不启用无条件自动放行。
